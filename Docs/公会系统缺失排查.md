# 公会系统缺失排查（工作笔记）

> 状态：只读调查结论，尚未实现。分支 `guild-fix`（创建时与 `master` 完全一致，工作树干净）。
> 用途：记录“公会名重复校验无回包”的根因与后续接入所需信息，供后续开发使用。
> 注意：本文是排查笔记，不是生效开发规范；结论需以当前 A21 抓包/客户端逆向重新验证。

## 1. 现象

- 客户端发起“公会名重复校验”请求，服务端**无任何回包**。
- 其余公会操作（创建、加入、成员、等级、仓库/运输、技能、公会副本、公会聊天等）同样无响应。

## 2. 根因

A21 的 CMD 分发表**没有注册任何公会 CMD 处理器**，命中兜底日志后直接返回，不回包。

- 分发入口：`Server\DfoServer\Network\Protocol\GameProtocolHandler.cs:305-311`
  - `_cmdDispatch.TryGetValue(header.type, out handler)` 未命中时进入 `else`，仅打印
    `[GameProtocol] Unhandled CMD type=0xXXXX ...`，不发送任何响应。
- 公会名重复校验 opcode 已声明但未注册：
  - `Server\DfoServer\Network\Core\PacketTypesA21.cs:1387` → `CHECK_GUILD_NAME_DOUBLE = 0x009C`
  - `GameProtocolHandler.cs` 各 `Register*Handlers` 中**没有** `0x009C` 注册项。
- 对照组（已实现，可作为实现模板）：角色名重复校验
  - `PacketTypesA21.cs:1924` → `CHECK_DOUBLE_CHARACTER_NAME = 0x02B5`
  - 注册：`GameProtocolHandler.cs:336` → `d[0x02B5] = _characterSelectHandler.Handle_ENUM_CMDPACKET_CHECK_DOUBLE_CHARACTER_NAME;`
  - 实现：`Server\DfoServer\Network\Handlers\CharacterSelectHandler.cs:831-872`
    - 解析 `[i32 nameLen][nameBytes]`
    - `NameInputValidator.TryValidateRawName`
    - `_characterRepository.GetByName(name)` 判重
    - 回包：`GamePacketEnvelopeBuilder.Build(0x01, 0x02B5, ...)`，重名用 `BuildCmdError(24)`，可用用 `BuildSuccessAck()`

结论：公会名校验无回包 = 公会 CMD 分发表整体缺失的直接结果，不是已有逻辑的 bug。

## 3. 证据：`GUILD_*` 枚举被声明但零消费

- `PacketTypesA21.cs` 声明约 130 个公会相关 opcode（NOTI/CMD）。
- 全仓库搜索：除 `PacketTypesA21.cs` 与旧副本 `PacketTypes.cs` 外，`GUILD_*` 无任何引用；
  无 `GuildService`、`GuildHandler`、`GuildRepository`、`GuildCoordinator`。
- 因此所有公会 CMD 均落入 `GameProtocolHandler.cs:310` 的 Unhandled 分支。
